## Glossary
- **Design document / doc:** the Loro CRDT holding a project's pages, nodes, components, variables, assets and code files.
- **Op / transaction:** a validated change to the doc; a transaction = one gesture or one agent turn = one undo step.
- **Generated files:** everything in Code View; produced by the compiler, read-only.
- **Embed:** a node holding sanitized third-party HTML or a URL (maps, videos, widgets); the only way to add custom markup.
- **Temp link:** hosted preview at `*.truframe.site` for client approval.
- **Credit:** unit of built-in agent usage (`docs/product/BILLING.md §3`). **MCP call:** one external tool call.

- Next.js `output: 'export'` can't use server features; temp links for Next.js projects are static in v1.

## Conventions learned
- 2026-11-24: Docs live in `docs/`: `product/` (PRD, BILLING, INTEGRATIONS), `engineering/` (ARCHITECTURE, SECURITY), `project/` (PLAN, TASKS, MEMORY), `prompts/`, `runbooks/`. Only `README.md`, `AGENTS.md`, `CLAUDE.md` and `LICENSE` stay at the root, because tools read them there. Reference docs by repo-root path. Index: `docs/README.md`.
- 2026-11-24: `.gitattributes` forces LF everywhere (Windows dev machines have `core.autocrlf=true`; goldens must be byte-identical).
- 2026-11-24: pnpm 11 enforces `minimumReleaseAge` (~1 day). Pin versions at least a day old instead of adding `minimumReleaseAgeExclude` entries. Install scripts are allowed only via `allowBuilds` in `pnpm-workspace.yaml` (esbuild, workerd).
- 2026-11-24: `worker-configuration.d.ts` is generated by `wrangler types` in each worker's `typecheck` script and gitignored (16k lines each). Package scripts run under cmd.exe on Windows: no `/dev/null` redirects.
- 2026-11-24: Repo scripts are plain `.ts` run with Node's built-in type stripping (`node scripts/x.ts`, Node ≥ 22.18): erasable syntax only, import with `.ts` extensions (`allowImportingTsExtensions` is in the base tsconfig).
- 2026-11-24: Run `pnpm check:licenses` after **every** dependency change; it is not part of `pnpm lint`. In P0-3, next brought in BlueOak/CC-BY packages that went unnoticed until the final clean-install run.
- 2026-11-24: `pnpm lint` = Biome CI + `scripts/check-deps.ts` (dependency rule) + `cargo fmt --check` + `cargo clippy -D warnings`. `pnpm check:licenses` = npm allowlist (`scripts/check-licenses.ts`, exceptions in `licenses.exceptions.json`) + `cargo deny check licenses bans sources`. Biome ignores Markdown (it would reflow the docs).
- 2026-11-24: One root `vitest.config.ts` (single project) includes `{apps,packages,workers,scripts}/**/*.test.ts(x)`. Worker tests run in Node with `cloudflare:workers` aliased to `test/cloudflare-workers-shim.ts`; switch to `@cloudflare/vitest-pool-workers` in P2. That pool needs **Vitest 4** (peer `^4.1.0`), which is why Vitest is pinned to 4.1.12, not 5.
- 2026-11-24: A worker's main module may export **only** entrypoints (default handler, DO classes, `WorkerEntrypoint`s). Exporting a plain constant makes workerd fail at startup ("Incorrect type for map entry"). Unit tests don't catch this; `pnpm dev` does.
- 2026-11-24: `@opennextjs/cloudflare build` fails on Windows with `EPERM symlink` (needs Developer Mode). Build/deploy the web worker on Linux (CI) or in Docker (`node:22-bookworm`). `next build` and `next dev` work on Windows.
- 2026-11-24: shadcn CLI in `packages/ui` resolves aliases via the package's tsconfig `paths` (`@truframe/ui/*` → `./src/*`) and needs a `hooks` export. It once rewrote an import to `from "cn"` and **installed an unrelated npm package `cn`**: review every `shadcn add` diff and package.json change.
- 2026-11-24: Wrangler bindings are not inherited by `env.*`; `scripts/lib/wrangler-config.test.ts` checks each env repeats them and points only at its own `truframe-<env>*` resources. Local dev ports: web 3000, realtime 8787, agent 8788, mcp 8789, jobs 8790, sites 8791.
- 2026-11-24: First GitHub CI run caught three Linux-only problems that local Windows runs missed. (1) Concurrent `wrangler dev` processes fail with `Address already in use (socket "direct:1:default")` unless each worker has a fixed `dev.inspector_port` (9230 to 9234). (2) `next build` type-checks against the gitignored `cloudflare-env.d.ts`, so the web `build` script runs `wrangler types` first. (3) On Linux, sharp's libvips is a separate `@img/sharp-libvips-<platform>` package licensed plain `LGPL-3.0-or-later`. Reproduce CI locally in `node:22-bookworm` via Docker before pushing infra changes.
- 2026-11-24: CI (`.github/workflows/ci.yml`): jobs lint, typecheck, unit, rust, build (incl. OpenNext + `wrangler deploy --dry-run --env staging`), e2e (Playwright starts `pnpm dev` and waits for `/api/health` = 200, i.e. all bindings up), deploy-staging (push to main, GitHub environment `staging`, then smoke e2e against `vars.STAGING_URL`). Actions are pinned to commit SHAs; Dependabot updates them weekly. Check workflow edits with `docker run --rm -v <repo>/.github:/w rhysd/actionlint -no-color /w/workflows/ci.yml`.
- 2026-11-24: D1 access: `createDb(env.DB)` per request, then `workspacesRepo(db)` (user → workspace memberships) and `forWorkspace(db, workspaceId)` (projects, usage, audit; every query filters on `workspace_id`). `@truframe/db` exports no tables except `authAdapterSchema` for Better Auth. A Biome `noRestrictedImports` override in `biome.json` blocks `drizzle-orm*` and `**/db/src/**` imports outside `packages/db`; `scripts/lib/table-imports.test.ts` proves it fires.
- 2026-11-24: Migrations: edit `packages/db/src/schema/*`, run `pnpm db:generate` (drizzle-kit writes `packages/db/migrations/NNNN_*.sql` and `meta/`), apply with `pnpm db:migrate` (wrangler, local). The web `dev` script applies local migrations before `next dev`. Wrangler ignores drizzle's `meta/` folder. D1 has no interactive transactions, so use `db.batch([...])`.
- 2026-11-24: DB tests use wrangler's `getPlatformProxy({ persist: false })` (a real workerd D1, in memory) through `@truframe/db/testing`. Miniflare 5 (the beta that wrangler 4.166 ships) changed its constructor API, so don't call `new Miniflare()` directly.
- 2026-11-24: `biome lint --stdin-file-path` does not apply `overrides` the way a real file does. Test lint rules against real temp files.
- 2026-11-24: Auth lives in `packages/auth` (`createAuth`) and is built per request in `apps/web/src/lib/server/context.ts` (`getServerContext`, React `cache`). Env is zod-validated by `parseAuthEnv`, which refuses unsafe deployed config (mock OAuth, Turnstile test keys, http URL, missing Resend key) and never echoes values. Owner steps: `docs/runbooks/auth-setup.md`.
- 2026-11-24: Better Auth refuses to link an OAuth sign-in to a user whose own email is unverified unless `accountLinking.requireLocalEmailVerified: false`. We set it false so the real owner of an address isn't locked out by someone who signed up with it first, and an `account.create.before` hook deletes that unverified password and its sessions (`authUsersRepo.dropUnverifiedCredentials`). Provider-unverified emails still never link.
- 2026-11-24: Mock OAuth for e2e: `TRUFRAME_OAUTH_MOCK=1` (local only) registers Google and GitHub through Better Auth's `genericOAuth` with the same provider ids, `getToken`/`getUserInfo` stubs, and an authorize page at `/api/dev/oauth/authorize`. Built-in Google/GitHub providers hard-code their token URLs, so they can't be pointed at a mock.
- 2026-11-24: Local emails: with no `RESEND_API_KEY` in local, the dev sender logs `[dev email] ... link=...` and keeps the last 10 per address in KV (`dev-mail:<email>`), readable at `/api/dev/mail?to=` (404 outside local). e2e reads links from there.
- 2026-11-24: Auth rate limits use Better Auth's D1 store (`rate_limits`), keyed by `cf-connecting-ip` when deployed and `x-forwarded-for` locally, so each e2e test sets its own `x-forwarded-for`.
- 2026-11-24: Keep OpenNext dev on the **default** Wrangler state (`apps/web/.wrangler`). `getCloudflareContext({ async: true })` falls back to its own `getPlatformProxy()` with default options when a module context lacks the global (route handlers can), so a custom `persist` path in `initOpenNextCloudflareForDev` creates a second, separate local D1/KV. Sessions written in one were missing in the other, and pages reloaded in a loop.
- 2026-11-24: Root `pnpm dev` is `turbo run dev --env-mode=loose`. With Turbo's default strict env mode, `next dev` on Windows lost env vars it needs, and every page reloaded forever (`[HMR] connected` → `[Fast Refresh] rebuilding` → reload). Plain `next dev` did not loop, and no files changed on disk.
- 2026-11-24: React Email: use the individual `@react-email/*` packages. The all-in-one `react-email` package now bundles a CLI (socket.io, esbuild, babel). `@react-email/render` has a `workerd` export. Resend is called with one `fetch` (no SDK).
- 2026-11-24: Better Auth hashes passwords with `node:crypto` scrypt when available, otherwise pure-JS `@noble/hashes`. Measure sign-up/sign-in CPU time on staging (Workers CPU limits).

- 2026-11-24: Pages that read the session or D1 must be `export const dynamic = "force-dynamic"`. Otherwise `next build` prerenders them, several build workers open the local D1 at once, and the build fails with `SQLITE_BUSY` (seen in CI, not on Windows).

- 2026-11-24: App API pattern: route handlers are wrapped in `withWorkspace()` (`apps/web/src/lib/server/api.ts`). Non-GET requests must carry the app's Origin; a session is required; the workspace comes from the session (`?workspace=` only if the user is a member); handlers get only repos bound to that workspace. Expected failures throw `ApiFailure` and become `{ error: { code, message } }` (codes in `packages/protocol`). Unknown project ids and other workspaces' ids both answer 404.
- 2026-11-24: e2e against `next dev`: the first hit to a route compiles it, which takes seconds, so Playwright's `expect.timeout` is 20 s. A click before hydration does nothing, so open dialogs with `openDialog()` (`e2e/helpers.ts`), which retries the click.

- 2026-11-24: Templates: `TEMPLATES` and `templateDocument(id)` in `@truframe/model`, with JSON fixtures in `packages/model/src/templates/`. Template ids are also an enum in `@truframe/protocol` (`TEMPLATE_IDS`); a model test keeps the two lists equal. The fixture format is provisional until P2-1.

- 2026-11-24: Plan limits: read them only through `@truframe/billing` (`limitFor`, `planForWorkspace`). Enforce counts inside the write: the repo methods take the limit (`createWithinLimit(input, max)`, `duplicate(..., { maxActive })`, `restore(id, now, max)`) and put `(select count(*) ...) < max` in the same statement. A count-then-insert in two queries lets concurrent requests overshoot. `UNLIMITED` is `Infinity`, which the repos treat as no check.
- 2026-11-24: Open issue (Windows only): when Playwright (or the whole `pnpm dev` stack) launches `next dev`, pages sometimes full-reload in a loop (`[HMR] connected` → `[Fast Refresh] rebuilding` → reload), with no file changes on disk. Plain `next dev`, started by hand, doesn't loop, and Linux CI passes. Workaround: start `pnpm --filter @truframe/web dev` yourself, then run `pnpm e2e` (it reuses a running server). Playwright starts only the web app; the health check needs bindings declared, not other workers running.
- 2026-11-24: Radix dialogs set `aria-hidden` on the rest of the page while open. Close the dialog before asserting on page content by role.
- 2026-11-24: Document model (`@truframe/model`): `validateDocument(x)` returns `{ ok, doc | issues[] }` with every problem (path + message), `parseDocument` throws for trusted input. zod checks shape (strict objects), `checkIntegrity` checks references. Layout and sizing are per-breakpoint style props. Templates are JSON outlines expanded by `templateDocument(id, { projectId, framework })`.
- 2026-11-24: Model parity: change `packages/model` → mirror it in `crates/compiler/src/model` → run `node scripts/model-fixtures.ts` and `pnpm format` → `pnpm test` and `cargo test`. Rust checks shape only (unknown keys, types, enums, required fields); ranges and references are the TS validator's job, so invalid fixtures hold only shape errors. Serde gotchas: `#[serde(default)]` on an `Option<T>` field of a generic struct adds a `T: Default` bound (leave it off, missing options are `None` anyway); compare round-tripped JSON with numbers normalized to f64 (`24` vs `24.0`).
- 2026-11-24: Ops property tests build each random op against the current document from fast-check numbers (`makeOp(doc, choice)`), so most ops are meaningful and some are deliberately invalid. Compare documents with `canonical()` (sorted keys): an undo re-inserts nodes at the end of the `nodes` map, so key order differs while the document is equal. The test asserts every op type gets applied at least once, so a generator change can't silently stop covering an op.
- 2026-11-24: loro.dev answers 403 to automated fetches. Read the API from the package itself: `npm pack loro-crdt@<v>` into the scratchpad, then `bundler/loro_wasm.d.ts` (classes) and `bundler/index.d.ts` (typed `LoroTreeNode`, `createNode`, `getNodes`), plus the README (bundler entries, mergeable children and undo identity).
- 2026-11-24: Loro facts we rely on: `loro-crdt` resolves the `nodejs` entry in Node/Vitest (sync WASM, no init); browsers use `browser`/`bundler`, and `loro-crdt/base64` inlines the WASM for esbuild/Rollup. `LoroMap.ensureMergeableMap(key)` keeps one container identity per parent/key; deleting and re-creating it brings back its old contents. Tree nodes need `enableFractionalIndex(0)` for ordered children. Changes are not visible to `export`/events until `doc.commit()`.
- 2026-11-24: `applyTransaction` must copy every op payload it stores in the document (`structuredClone`). Before the fix, an `addPage` followed by `insertNodes` into that page in the same transaction mutated the returned parsed `addPage` op, and the Loro binding then built a page body with a child it didn't have. The Loro property test found it.
- 2026-11-24: Realtime worker: `loro-crdt` must be aliased to `loro-crdt/base64` in `workers/realtime/wrangler.jsonc` (the default entry fetches its `.wasm` by URL, which workerd can't do). Node and Vitest keep the default `nodejs` entry.
- 2026-11-24: Worker integration tests use Wrangler's `createTestHarness()` (the replacement for the deprecated `unstable_startWorker`/`unstable_dev`): `server.listen()` gives a URL for real WebSockets (Node 22 global `WebSocket`), `getWorker().applyD1Migrations("DB")`, `getEnv()` for bindings (drizzle works on the proxied D1), `getDurableObjectStorage(binding, { name })` to read DO SQLite. Pass test secrets with `secrets: {...}` and test vars with `vars: {...}`. `room.integration.test.ts` boots in a few seconds and runs in the normal `pnpm test`.
- 2026-11-24: `ROOM_TOKEN_SECRET` (≥ 32 chars) must be the same in `apps/web/.dev.vars` and `workers/realtime/.dev.vars`; both `.dev.vars.example` files hold the same local value. The web app also needs `TRUFRAME_REALTIME_URL` (`ws://localhost:8787` locally, `wss://` required elsewhere).
- 2026-11-24: Fixed flake: the ops property test sometimes failed its "every op type applied" check because `setInstanceOverride` only applied when the random node happened to be the single instance in the kitchen-sink document, so some 1,000-run batches never applied it (seen in CI, PR #18). The generator now aims that op at instance nodes. When a coverage check in a property test fails, make the generator reach that case more often instead of loosening the check. `OPS_PROPERTY_RUNS=10000` runs a longer local search.
