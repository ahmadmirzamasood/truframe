Repo-level isolation tests are in `packages/db` (P1-1) and `packages/auth` (`resolveWorkspace`). The socket, R2, MCP and agent parts of T1 belong to P2/P7.

## P2 Document core and realtime
- [x] **P2-1** `packages/model`: schema per `docs/engineering/ARCHITECTURE.md §5` (zod), defaults (Desktop 1200, Tablet 810, Mobile 390), breakpoint range validation (desktop ≥ 1200 and not deletable). *Done when* unit tests cover valid/invalid docs. `packages/model/src/document.test.ts` (valid docs, breakpoint ranges, every integrity rule) and `templates.test.ts` (all four templates expand to valid documents for both frameworks). Schema choices are in ARCHITECTURE §5 "Schema details".
- [x] **P2-2** Rust model mirror in `crates/compiler/src/model` + JSON parity test against TS fixtures. *Done when* CI parity job passes. Serde types in `crates/compiler/src/model` reject unknown keys. Fixtures in `fixtures/model/{valid,invalid}` come from `node scripts/model-fixtures.ts` (templates, a kitchen-sink doc covering every shape, a desktop-only doc; 11 shape errors). CI job "Model parity (TypeScript ↔ Rust)" runs `packages/model/src/parity.test.ts` (fixtures match the generator and the TS validator) and `cargo test --test parity` (every valid fixture round-trips to the same JSON, every invalid one is rejected).
- [x] **P2-3** `packages/ops`: op types, validation (schema + plan limits), transactions, inverse ops. *Done when* property test (random ops keep doc valid; undo restores) passes 1,000 runs. 15 ops (`insertNodes`, `deleteNode`, `moveNode`, `setProp`, `resetProp`, `setNodeFields`, `setInstanceOverride`, `addPage`, `deletePage`, `updatePage`, `movePage`, `setBreakpoint`, `upsertVariable`, `deleteVariable`, `setSettings`). `applyTransaction(doc, ops, limits)` parses untrusted ops, applies them to a copy, validates the whole result (schema, references, `pagesPerProject` on growth) and returns the inverse ops. `apply.property.test.ts` runs 1,000 random runs of up to 25 transactions over templates and a kitchen-sink doc: results stay valid, failed transactions change nothing, undo and redo are exact, and every op type is exercised. Component ops (`createComponent`, `detachInstance`, component edits) and `addAsset` come with their features in P5.
- [x] **P2-4** Loro binding: doc layout in Loro containers, op → Loro mutation, export/import updates. *Done when* round-trip tests pass. `packages/crdt` (`@truframe/crdt`): `documentToLoro`, `loroToDocument`, `applyOpToLoro`, `applyTransactionToLoro` (validates with `applyTransaction`, then mutates Loro in one commit). `binding.test.ts`: every model fixture round-trips through Loro and a snapshot; updates carry only new changes; concurrent edits to different props both survive; concurrent moves never duplicate a node; edits inside a deleted subtree are dropped; and a 300-run property test shows Loro matches `applyTransaction` op for op and a replica converges from updates.
- [x] **P2-5** ProjectRoom DO: room tokens (HMAC, 5 min), WebSocket hibernation API, apply/broadcast, SQLite persistence, R2 snapshot compaction, revision rows in D1. *Done when* T2 passes and two clients converge. Room tokens: `packages/protocol/src/room.ts` (HMAC-SHA256, 5 min, bound to user, workspace, project, role and plan; sent as the second WebSocket subprotocol), issued by `POST /api/projects/:id/room-token`. `workers/realtime`: the router verifies the token and forwards to `ProjectRoom`, which validates every transaction with `applyTransactionToLoro`, persists the update in DO SQLite, broadcasts it, acks resends by tx id, and compacts every 200 updates or 5 minutes (snapshot in SQLite and R2, revision row in D1, `revisions` table). Evidence: `room.integration.test.ts` (Wrangler `createTestHarness`, real workerd): T2 (missing, forged, expired and other-project tokens refused), the socket part of T1 (other workspace refused), two clients converge, invalid and viewer transactions rejected, resends idempotent, delta sync, and stored snapshot + updates, the R2 snapshot and D1 revisions match the clients; `room.test.ts` (tokens); `e2e/isolation.spec.ts` (only the owning workspace gets a token).
- [x] **P2-6** Editor client store: Loro replica, IndexedDB cache, reconnect sync, undo/redo stacks per user. *Done when* offline edit then reconnect converges (e2e). `packages/sync` (`DocClient`): a Loro replica fed only by the room, pending transactions shown on top and resent after every reconnect (the room dedupes by id), IndexedDB cache of the snapshot and pending edits, backoff reconnect plus browser online/offline events, and per-user undo/redo through inverse ops (steps that no longer apply are skipped). `/p/[projectId]` is a minimal editor shell (status, layers, add text, undo/redo) until P4. Evidence: `packages/sync/src/client.test.ts` (7 tests against an in-memory room) and `e2e/editor-sync.spec.ts`: two browsers stay in sync, an offline browser keeps editing and converges on reconnect, a reload restores the same document, undo removes only your own change, and other users get 404.
